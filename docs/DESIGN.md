| `ws` | 풍속 | m/s | 풍속(m/s) | |

### 2-2. 학습 행(`core.buildFeatures`, 웹앱 안에서 계산)
| 특성 | 정의 |
|---|---|
| `dp3` | 지금 현지기압 − 정확히 3시간 전 현지기압 (hPa, 0.1 단위) |
| `rh`, `ta`, `ws` | 그 시각 값 |
| `south` | 풍향 16방위 중 남동·남남동·남·남남서·남서(6~10번)면 1. 풍속 0.3 m/s 미만 = 정온(0). 풍향 결측 = 행 제외 |
| `hour` | 관측 시각(0~23시) — 기압의 하루 두 번 오르내림(오후에 낮아짐)을 AI가 구분하도록 |
| `rain`(정답) | 다음 1~H시간 강수량 합 ≥ 0.1 mm 이면 1 (H 기본 6, `?h=12/24` 가능) |
| 제외 | 3시간 전 기압, 이후 H시간 기록, 기온·습도·풍속·풍향 중 하나라도 없으면 그 행 제외 |

- 학습: 처음~(끝−3)년, 시험: 마지막 3년(2016–2025면 2016–2022 / 2023–2025). **03 가설 검증도 학습 기간만** 써서 규칙 예보관도 시험 기간을 미리 보지 않음
- 정답 이름: “비” / “비 안 옴”(흐림 포함). ‘맑음’은 하늘 상태 용어라 쓰지 않음
- 의사결정트리: CART · 지니 · 깊이 3(조정 2~4) · 잎 최소 1%(최소 100행) · 후보 경계 = 학습 자료 5~95% 분위(표시 단위로 반올림해 **화면 숫자 = 실제 경계**)
- 가중 학습: 비 행 가중치 = 학습 자료의 (비 안 옴 행 수 ÷ 비 행 수)
- 가설 판정(수업용, 통계 검정 아님): 배수 = P(비|조건) ÷ P(비|전체). ≥1.5 지지 · ≥1.1 약하게 지지 · 0.9~1.1 기각(차이 없음) · <0.9 기각(반대) · 조건 행 < 50 판단 보류

## 3. 기상청 ASOS 10년 자료 확보 방법

**기상자료개방포털 내려받기**
1. data.kma.go.kr 로그인 → 데이터 › 기상관측 › 지상 › 종관기상관측(ASOS) › **자료** 탭
2. 자료형태 **시간 자료** · 지점 서울(108) · 요소 기온, 강수, 바람, 기압, 습도
3. 포털 제한: **시간 자료는 1회 최대 1년**(분 1일, 일 10년) → 2016~2025년을 한 해씩 10번 조회해 CSV로 받음. 장기간은 ‘파일셋’ 탭(ZIP)도 가능
4. `teacher.html` ① 상자에 CSV·ZIP을 **한꺼번에 끌어다 놓기**(여러 번 나눠 넣어도 누적, 순서·중복 무관, EUC-KR/UTF-8 자동 판별)
5. 연도별 행 수 표(그해 전체 시간 대비 98% 이상 ✔)와 경고(빠진 해, 다른 지점 섞임, 기압·바람 열 비어 있음) 확인
6. `asos_108_hourly.csv`(약 3~4 MB) 내려받기 → `data/`에 넣고 커밋. 커밋 전에는 **“이 브라우저에서 바로 써 보기”**(IndexedDB)로 학생 화면을 먼저 시험
7. 변환기가 만든 **데이터 카드**를 `data/README.md`에 붙임

포털 안내: 겨울철(11월~이듬해 3월) 강수량은 3시간 간격으로 제공될 수 있음 → 6시간 창 판정이라 영향이 작지만 데이터 카드에 명시. 전날 자료는 당일 10시 이후 확인 가능(3차시 채점 시점 참고).

> 개발 중 시험은 **합성 자료**로만 했습니다. 합성 자료는 저장소에 넣지 않았고, 실제 수치(비 온 시간 비율, 정확도 등)는 원자료를 넣은 뒤에 확정합니다.

## 4. 실시간 데이터 파이프라인

```
[창가] 무선 날씨센서 PS-3209 ─BLE─ 교사 PC: bridge/pasco_bridge.py (30초 측정 · 60초마다 전송 · 로컬 CSV 백업)
        └─ POST {kind:'live'} ─→ Apps Script ─→ live 시트 + 캐시('latest') 즉시 갱신
학생 크롬북 ─ JSONP GET ?action=latest ─→ 캐시 응답(25초) ─→ 실시간 패널 · 입력값 자동 채움
[교내] 무선 온도센서 ×5 ─BLE─ 모둠 크롬북 sparkvue.pasco.com ─ CSV ─→ 웹앱 업로드 ─ POST {kind:'obs'}
[예비] 브리지 실패 시 브리지를 끄고 SPARKvue로 센서 연결 → 데이터 스트리밍 · [안전장치] 날씨센서 로깅 모드(로깅 중 브리지 연결 가능 여부는 사전 시험)
※ 센서는 실외 그늘·통풍되는 곳(관측소 조건: 백엽상 기온·습도, 10 m 풍속과 다름을 화면에 표시)
```

### 4-1. SPARKvue CSV 병합 규칙 (Q1 — 2026-10-27 실제 내보내기 파일 기준)
실제 파일 머리글: `"일시 실행 1","시간 (s) 실행 1","온도, xxx-005 (°C) 실행 1","상대 습도 (%) 실행 1",…,"기압 (mmHg) 실행 1","풍속 (km/hr) 실행 1",…`
1. **실행 번호 분리**: 끝의 `실행 N`(영문 `Run N`·`Run #N`)으로 열을 묶음. 한 파일에 여러 실행이 있으면 학생이 고름(기본 = 마지막)
2. **단위는 마지막 괄호**: `(mmHg)` → ×1.333224 hPa, `(km/hr)` → ÷3.6 m/s. 원자료 758.6 mmHg = 1011.4 hPa
3. **열 종류는 이름으로**: 일시/온도/상대 습도/기압/풍속만 사용. 이슬점·풍랭·Humidex·절대 습도·GPS(위성 계수 0이면 위도·경도 0 = 무의미)·UV·조도는 버림
4. **시각**: `일시` 열(`2026/10/27 14:20:45`, KST, 1초 간격)을 씀. 없으면 학생이 시작 시각 입력 + `시간 (s)`
5. **빈 행 제거**: 측정 끝 무렵 일부 열만 비는 행이 있음(실제 파일 마지막 6행) → 온도·습도·기압이 모두 빈 행만 버림
6. **1분 평균**으로 묶어 전송(20분 = 20행) → 모둠 파일 5개는 `반-모둠 + 지점` 키로 시트에서 합쳐짐(파일명에 의존하지 않음)

### 4-2. 동시 접속 캐싱 (Q3)
- 학생 요청은 시트를 읽지 않고 `CacheService` 문자열을 돌려줌(`obs`·`forecasts` 20초)
- 브리지가 60초마다 값을 넣을 때 `latest` 캐시를 **지우지 않고 새로 만들어 60초 동안** 넣어 둠 → 수업 중 시트 읽기는 사실상 1분에 한 번
- 캐시 한도(값 하나 100KB)는 **바이트**로 재고(한글 3바이트), 넘치면 캐시 없이 응답
- 마지막 센서 기록이 10분보다 오래되면 학생 화면에 경고
- 계열은 최근 6시간, 400점 이하로 솎아 캐시 100KB 한도 안에 둠
- 학생 화면은 버튼을 누를 때만 요청(자동 새로고침 없음) → 10명 이하 접속이면 동시 실행 한도(30)에 여유
- 쓰기는 `LockService`로 줄 세움
